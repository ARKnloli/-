# 蓝牙小车简化方案

## 背景

当前蓝牙通信不工作。分析发现根本原因是：**协议太复杂**（5字节帧+校验），APP发送的数据可能不符合协议格式，导致STM32收不到有效命令。

参考 https://github.com/daohewang/Bluetooth-intelligent-car 的极简单字节协议，将我们的蓝牙协议简化为单字节ASCII字符。

## 修改计划

### 步骤1：简化蓝牙协议（bluetooth.h）

**修改文件**: `lanyaxc/Core/Inc/bluetooth.h`

删除复杂帧格式定义，改为单字节命令：

| ASCII字符 | HEX值 | 功能 |
|-----------|-------|------|
| '0' | 0x30 | 停止 |
| '1' | 0x31 | 前进 |
| '2' | 0x32 | 后退 |
| '3' | 0x33 | 左转 |
| '4' | 0x34 | 右转 |
| '5' | 0x35 | 加速 |
| '6' | 0x36 | 减速 |

删除：帧头定义、状态机枚举、回调函数类型

### 步骤2：简化蓝牙接收（bluetooth.c）

**修改文件**: `lanyaxc/Core/Src/bluetooth.c`

- 删除状态机逻辑
- 中断回调中直接判断字符，设置全局flag
- 不在中断中执行任何业务逻辑（只设flag）
- 删除调试用的蜂鸣器翻转代码

### 步骤3：更新主程序（main.c）

**修改文件**: `lanyaxc/Core/Src/main.c`

- 主循环中用switch-case处理蓝牙命令
- OLED显示更新在主循环中执行
- 蜂鸣器响应在主循环中执行（不在中断中）
- 恢复完整的OLED显示功能（方向+速度）

### 步骤4：验证

编译烧录后，APP测试：
- HEX模式发送 `30` → 停止
- HEX模式发送 `31` → 前进
- HEX模式发送 `32` → 后退
- HEX模式发送 `33` → 左转
- HEX模式发送 `34` → 右转

## 涉及文件

| 文件 | 操作 |
|------|------|
| `lanyaxc/Core/Inc/bluetooth.h` | 简化协议定义 |
| `lanyaxc/Core/Src/bluetooth.c` | 简化接收逻辑 |
| `lanyaxc/Core/Src/main.c` | 更新调度逻辑 |

## 验证方法

1. 编译无错误
2. 烧录后OLED显示"Smart Car"和方向/速度
3. APP发送 `31`（前进），OLED显示"FWD"，电机转动
4. APP发送 `30`（停止），OLED显示"STOP"，电机停止
5. 每个命令蜂鸣器响一声确认
